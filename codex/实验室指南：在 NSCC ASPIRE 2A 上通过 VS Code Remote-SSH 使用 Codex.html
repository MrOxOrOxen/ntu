实验室指南：在 NSCC ASPIRE 2A 上通过 VS Code Remote-SSH 使用 Codex

方括号里的内容要换成你自己的信息；密码只在本机终端的提示处输入，不要发给任何人。

1. 先看完这几条

  • 这套做法只用于 NSCC 的 login node。训练、推理、长时间运行和高资源任务仍然要通过 PBS 提交。
  • 你需要保持两个本机终端开着：一个运行 proxy，另一个保持 SSH 连接。
  • 不要把密码、API key、token 或 ~/.codex/auth.json 发到聊天、文档或截图里。
  • 所有端口都只使用 127.0.0.1；不要改成 0.0.0.0，也不要开启 GatewayPorts。
  • 本机休眠、换网络或 VPN 断开后，通常需要重新启动 SSH 连接并测试一次。

2. 先填好自己的信息

本页后面的命令会用到这些值：

  • [NSCC_USER]：你的 NSCC 用户名。
  • [NSCC_HOST]：你的机构对应的 NSCC 入口。NTU 用户通常是 aspire2antu.nscc.sg；其他用户请查看 NSCC 官方说明。
  • [LOCAL_PORT]：本机 proxy 端口。建议先用 8899。
  • [REMOTE_PORT]：NSCC login node 上的临时端口。建议先用 17891，但必须先测试它是否可用。
  • SSH alias：建议统一命名为 nscc。

下面所有出现 [NSCC_USER]、[NSCC_HOST]、[LOCAL_PORT]、[REMOTE_PORT] 的地方，都要替换成自己的值。不要把方括号一起复制进命令。

3. macOS：先启动本机 proxy

打开一个新的 Terminal 窗口。这个窗口之后要一直开着。

第一次使用时运行：

python3 -m venv "$HOME/.local/share/nscc-codex-proxy"
"$HOME/.local/share/nscc-codex-proxy/bin/pip" install --upgrade pip proxy.py

然后启动 proxy：

"$HOME/.local/share/nscc-codex-proxy/bin/proxy" \
  --hostname 127.0.0.1 \
  --port [LOCAL_PORT] \
  --num-workers 1 \
  --num-acceptors 1

不要关闭这个窗口。再开第二个 Terminal 窗口，检查 proxy 是否正常：

lsof -nP -iTCP:[LOCAL_PORT] -sTCP:LISTEN
curl -sS -o /dev/null -w 'HTTP_%{http_code}\n' \
  --connect-timeout 10 \
  --max-time 20 \
  --proxy http://127.0.0.1:[LOCAL_PORT] \
  https://api.openai.com/v1/models

你应该看到：

  • lsof 输出里有 127.0.0.1:[LOCAL_PORT]。
  • curl 通常显示 HTTP_401。这表示网络路径已通，只是这条测试请求没有 API 凭据，属于正常结果。
  • 若看到 HTTP_000 或 connection refused，先回到第一个窗口，确认 proxy 仍在运行。

4. macOS：先做一次不改配置的 SSH 测试

仍在第二个 Terminal 窗口运行下面命令。它不会使用你现有的 SSH 配置，因此适合第一次测试。

ssh -tt -F /dev/null \
  -o PreferredAuthentications=keyboard-interactive,password \
  -o PubkeyAuthentication=no \
  -o ExitOnForwardFailure=yes \
  -R 127.0.0.1:[REMOTE_PORT]:127.0.0.1:[LOCAL_PORT] \
  [NSCC_USER]@[NSCC_HOST] \
  "hostname; curl -sS -o /dev/null -w 'HTTP_%{http_code}\n' \
    --connect-timeout 10 --max-time 20 \
    --proxy http://127.0.0.1:[REMOTE_PORT] \
    https://api.openai.com/v1/models; echo"

SSH 出现密码提示时，直接在 Terminal 输入你的密码。输入时屏幕不会显示字符，这是正常的。

成功的标志是：

  1. 输出一个 NSCC login node 名称。
  1. 随后出现 HTTP_401。

如果出现 remote port forwarding failed for listen port，先换一个未使用的高端口，例如 [REMOTE_PORT] 加 1，再做一次同样测试。第二次仍然失败时请停止，不要继续换端口或使用其他转发方式；见第 11 节。

5. macOS：写入 SSH 配置并启动稳定连接

5.1 备份配置

mkdir -p ~/.ssh
test -f ~/.ssh/config && cp ~/.ssh/config ~/.ssh/config.before-nscc-codex
touch ~/.ssh/config
chmod 600 ~/.ssh/config
mkdir -p ~/.ssh/sockets
chmod 700 ~/.ssh/sockets

5.2 编辑 ~/.ssh/config

打开 ~/.ssh/config。若文件里已有 Host nscc，请修改那一段；不要额外再写一个同名 Host nscc。

加入或更新为：

Host nscc
  HostName [NSCC_HOST]
  User [NSCC_USER]
  PreferredAuthentications keyboard-interactive,password
  PubkeyAuthentication no
  ServerAliveInterval 60
  ServerAliveCountMax 3
  ExitOnForwardFailure yes
  RemoteForward 127.0.0.1:[REMOTE_PORT] 127.0.0.1:[LOCAL_PORT]
  ControlMaster auto
  ControlPath ~/.ssh/sockets/%C
  ControlPersist 600

保存后检查 SSH 是否读到了正确设置：

ssh -G nscc | rg -i 'hostname|user|remoteforward|controlmaster|controlpath|controlpersist'

确认输出中有你的主机、用户名和两个端口。

5.3 启动连接并再次测试

如果之前有旧的 master 正在运行，先执行：

ssh -O exit nscc

若显示没有 master，可以忽略，继续下一步。

启动新的 master：

ssh -MNf nscc
ssh -O check nscc

预期会看到 Master running。接着运行：

ssh nscc "hostname; curl -sS -o /dev/null -w 'HTTP_%{http_code}\n' \
  --connect-timeout 10 --max-time 20 \
  --proxy http://127.0.0.1:[REMOTE_PORT] \
  https://api.openai.com/v1/models; echo"

看到 login node 名称和 HTTP_401 后，macOS 的 SSH 部分就完成了。

6. Windows：请使用 WSL2

Windows 用户建议使用 WSL2 的 Ubuntu 来运行 proxy 和 SSH。不要把正式的 SSH 隧道建立在原生 Windows OpenSSH 上；WSL2 的做法更稳定。

6.1 安装 WSL2 和基本工具

如果尚未安装 WSL2，请先按 Microsoft 的 WSL 文档安装 Ubuntu。打开 Ubuntu 终端，运行：

sudo apt update
sudo apt install -y python3 python3-venv openssh-client curl
mkdir -p ~/.ssh/sockets
chmod 700 ~/.ssh ~/.ssh/sockets

6.2 在 WSL 的 SSH 配置中加入 nscc

在 Ubuntu 终端编辑 ~/.ssh/config，并加入下面内容：

Host nscc
  HostName [NSCC_HOST]
  User [NSCC_USER]
  PreferredAuthentications keyboard-interactive,password
  PubkeyAuthentication no
  ServerAliveInterval 60
  ServerAliveCountMax 3
  ExitOnForwardFailure yes
  RemoteForward 127.0.0.1:[REMOTE_PORT] 127.0.0.1:[LOCAL_PORT]
  ControlMaster auto
  ControlPath ~/.ssh/sockets/%C
  ControlPersist 600

然后运行：

chmod 600 ~/.ssh/config

接下来在 Ubuntu 终端中，按照第 3、4、5.3 节的顺序完成：

  1. 启动 proxy。
  1. 做一次 fresh-port 测试。
  1. 运行 ssh -MNf nscc。
  1. 运行 ssh -O check nscc。
  1. 用 ssh nscc 做 HTTP_401 测试。

注意：proxy 必须运行在同一个 WSL Ubuntu 里，而不是 Windows PowerShell 里。

6.3 让 Windows 版 VS Code 使用 WSL 的 SSH

在 Windows PowerShell 中运行：

New-Item -ItemType Directory -Force "$env:USERPROFILE\bin"
notepad "$env:USERPROFILE\bin\wsl-ssh.cmd"

在打开的文件中粘贴：

@echo off
"%SystemRoot%\System32\wsl.exe" -d Ubuntu -- /usr/bin/ssh %*

保存并关闭。若你的 WSL 发行版名称不是 Ubuntu，先在 PowerShell 运行 wsl -l -q，然后把上面的 Ubuntu 改成显示的实际名称。

接着创建 Windows 的 SSH 主机列表文件：

New-Item -ItemType Directory -Force "$env:USERPROFILE\.ssh"
notepad "$env:USERPROFILE\.ssh\config"

在文件中粘贴：

Host nscc
  HostName [NSCC_HOST]
  User [NSCC_USER]

保存后，打开 VS Code 的用户 settings.json。保留已有设置，只增加这两项：

{
  "remote.SSH.path": "C:\\Users\\[WINDOWS_USER]\\bin\\wsl-ssh.cmd",
  "remote.SSH.configFile": "C:\\Users\\[WINDOWS_USER]\\.ssh\\config"
}

将 [WINDOWS_USER] 换成 Windows 登录名。然后在 PowerShell 验证：

& "$env:USERPROFILE\bin\wsl-ssh.cmd" -G nscc

若能输出 SSH 配置，就可以在 VS Code 中选择 nscc 连接。Windows 用户在整个使用期间也要保持 WSL 的 proxy 和 SSH master 存活。

7. 在 VS Code 中连接 NSCC

  1. 在本机 VS Code 安装 Remote - SSH 扩展。
  1. 按 Cmd/Ctrl+Shift+P，运行 Remote-SSH: Connect to Host...。
  1. 选择 nscc，不要选裸主机名或 IP。
  1. 连接成功后，在远端窗口打开自己的 NSCC 工作目录。
  1. 在窗口左下角确认显示 SSH: nscc。
  1. 在这个远端窗口安装或启用 Codex（OpenAI）扩展。

如果 VS Code 设置中有下面这种内容，请删除后 reload：

"remote.extensionKind": {
  "openai.chatgpt": ["ui"]
}

不要手动添加 remote.extensionKind 设置。

8. 在 NSCC 上设置 Codex

下面的操作在已经连接到 nscc 的远端终端中完成。

8.1 先确认你在 login node

hostname
printf 'PBS_JOBID=%s\n' "$PBS_JOBID"

PBS_JOBID 通常为空，表示你在 login node。这是本节应进行配置的位置。

8.2 编辑 .bashrc

先做备份：

cp ~/.bashrc ~/.bashrc.before-nscc-codex

然后用你习惯的编辑器打开 ~/.bashrc，将下面内容放到文件最上面。一定要放在任何“非交互 shell 直接退出”的语句之前。

# >>> nscc-codex-proxy >>>
if [[ "$(hostname -s)" == asp2a-login-* ]]; then
+  export HTTP_PROXY="http://127.0.0.1:[REMOTE_PORT]"
+  export HTTPS_PROXY="$HTTP_PROXY"
+  export http_proxy="$HTTP_PROXY"
+  export https_proxy="$HTTPS_PROXY"
+  export NO_PROXY="localhost,127.0.0.1,::1"
+  export no_proxy="$NO_PROXY"
+  export PATH="$HOME/.local/bin:$PATH"
+fi
+# <<< nscc-codex-proxy <<<
+```

保存后，退出远端终端并重新运行 ssh nscc。重新登录后测试：

printf 'HTTP_PROXY=%sn' "$HTTP_PROXY"


应该显示 http://127.0.0.1:[REMOTE_PORT]。

注意：上面代码中第一行 if 前面不要保留加号；那是本页排版符号，不是命令的一部分。

### 8.3 设置 VS Code Server 环境

先检查文件是否已经存在：

ls -l "$HOME/.vscode-server/server-env-setup" 2>/dev/null || true


如果文件不存在，可直接复制下面整段命令。如果它已存在，请只合并下面带 nscc-codex-proxy 标记的内容，不要删除自己的其他设置。

mkdir -p "$HOME/.vscode-server"

cat > "$HOME/.vscode-server/server-env-setup" <<'EOF'

#!/bin/sh

>>> nscc-codex-proxy >>>

case "$(hostname -s)" in

asp2a-login-*)

export HTTP_PROXY="http://127.0.0.1:[REMOTE_PORT]"

export HTTPS_PROXY="$HTTP_PROXY"

export http_proxy="$HTTP_PROXY"

export https_proxy="$HTTPS_PROXY"

export NO_PROXY="localhost,127.0.0.1,::1"

export no_proxy="$NO_PROXY"

export PATH="$HOME/.local/bin:$PATH"

;;

esac

<<< nscc-codex-proxy <<<

EOF

chmod 600 "$HOME/.vscode-server/server-env-setup"

sh -n "$HOME/.vscode-server/server-env-setup"


最后一条没有输出就表示脚本格式正常。

### 8.4 安装并登录 Linux 版 Codex

仍在 login node 运行：

curl -fsSL https://chatgpt.com/codex/install.sh | sh

export PATH="$HOME/.local/bin:$PATH"

command -v codex

codex --version

codex login status


如果显示尚未登录，运行：

codex login


按屏幕提示完成登录。不要复制或发送任何登录代码、token 或认证文件内容。

可选测试。它会实际发起一次 Codex 请求：

codex exec --ephemeral --sandbox read-only --skip-git-repo-check -C /tmp \

'Reply with exactly: READY. Do not use tools, run commands, or modify files.'


看到 READY 且命令正常结束，就说明远端 Codex 可以工作。

## 9. 重启 VS Code 后开始使用

完成第 8 节后，回到 VS Code：

1. 先保存未提交的工作。
2. 按 Cmd/Ctrl+Shift+P。
3. 运行 Remote-SSH: Kill VS Code Server on Host...。
4. 选择 nscc。
5. 再运行 Remote-SSH: Connect to Host...，重新选择 nscc。
6. 在远端窗口打开 Codex，确认它能读取和编辑工作区文件。

如果 Codex 一直显示 reconnect，先不要反复重装扩展。先到第 10 节做检查。

## 10. 日常使用与常见问题

### 每次开始工作

1. 启动本机或 WSL 中的 proxy，并保持窗口打开。
2. 运行 ssh -MNf nscc。
3. 运行 ssh -O check nscc。
4. 运行下面测试：

ssh nscc "hostname; curl -sS -o /dev/null -w 'HTTP_%{http_code}n' \

--connect-timeout 10 --max-time 20 \

--proxy http://127.0.0.1:[REMOTE_PORT] \

https://api.openai.com/v1/models; echo"


出现 hostname 和 HTTP_401 后，再打开 VS Code。

### 本机显示 HTTP_000 或 connection refused

proxy 没有运行，或者端口写错。回到运行 proxy 的窗口重新启动它，再重做本机 curl 测试。

### ssh -O check nscc 失败

SSH master 已断开。先运行：

ssh -O exit nscc

ssh -MNf nscc

ssh -O check nscc


然后重做上面的 HTTP_401 测试。

### VS Code 能连上，但 Codex 反复 reconnect

按这个顺序处理：

1. 确认 proxy 还在运行。
2. 确认 ssh -O check nscc 显示 Master running。
3. 确认 ssh nscc 的 HTTP 测试能看到 HTTP_401。
4. 确认 ~/.vscode-server/server-env-setup 存在且 sh -n 没有输出。
5. 用 Remote-SSH: Kill VS Code Server on Host... 重启远端 VS Code Server。

### 远端端口测试被拒绝

如果 fresh-port 测试两次都显示 remote port forwarding failed，请停止配置。不要尝试公网监听、GatewayPorts、SOCKS 或不断扫描端口。

可以向 NSCC support 说明：你需要一个仅限 127.0.0.1 的用户级 SSH 反向转发，格式为 -R 127.0.0.1:远端端口:127.0.0.1:本机端口；不需要公网监听或服务器配置改动。

## 11. PBS：重型任务要这样做

login node 只做编辑、轻量检查和提交任务。训练、推理、GPU 工作、长时间运行的程序都通过 PBS。

例如创建 job.pbs：

#!/bin/bash

#PBS -N experiment

#PBS -l select=1:ncpus=[NCPU]:mem=[MEMORY]

#PBS -l walltime=[HH:MM:SS]

#PBS -j oe

cd "$PBS_O_WORKDIR"

module purge

module load [required-module]

python run_experiment.py


按你的项目要求填写资源参数后，提交并查看状态：

qsub job.pbs

qstat -u "$USER"


不要在 compute node 中依赖本页的 127.0.0.1:[REMOTE_PORT]。它只属于 login node 的 SSH 连接。

## 12. 结束工作时

先关闭 SSH master：

ssh -O exit nscc


然后回到 proxy 窗口按 Ctrl-C 停止它。

## 13. 最后检查

- [ ] proxy 只监听 127.0.0.1:[LOCAL_PORT]。
- [ ] fresh-port 测试显示 hostname 和 HTTP_401。
- [ ] ssh -O check nscc 显示 Master running。
- [ ] VS Code 用 nscc alias 连接。
- [ ] 远端 codex --version 和 codex login status 正常。
- [ ] Codex 能在远端工作区读写文件。
- [ ] GPU/训练/推理等重型工作通过 PBS 提交。
